# batch (Batch resource types)

## Overview
Type definitions for the `crate::batch` NIF module. The NIF handlers themselves (`b_*`) live in the parent file [`../batch.rs`](../batch.rs); this directory holds only `types.rs`, which wraps the driver's `scylla::statement::batch::Batch` as a Rustler resource and mirrors `BatchType` as an Elixir atom enum.

## Interface
- `types.rs`
  - `BatchResource(pub Batch)`: Rustler resource (`impl rustler::Resource`, `RefUnwindSafe`). Registered in `../lib.rs` `load/2`. Elixir sees it as an opaque `reference()`.
  - `ScyllaBatchType` (`NifUnitEnum`, generated by `clone_enum!`): `Logged | Unlogged | Counter` (Elixir atoms `:logged`, `:unlogged`, `:counter`), with `From` conversions in both directions to `scylla::statement::batch::BatchType`.

## Invariants
- `ScyllaBatchType` variants must stay a 1:1 copy of the driver's `BatchType`. `clone_enum!` (in `../utils.rs`) generates exhaustive `match` arms in both directions, so adding or removing a driver variant breaks compilation until this list is updated.
- `BatchResource` is treated as immutable: every `b_set_*` / `b_append_statement` handler in `../batch.rs` clones the inner `Batch` (`to_owned()`) and returns a new `ResourceArc<BatchResource>`. The exception is `b_set_retry_policy/2`, which returns `:not_implemented_yet`.
- `b_new_with_statements` and `b_append_statement` decode statements as `ScyllaBatchStatement` from `../session/types.rs`, so changes there affect batches.
- The resource type must stay registered in `../lib.rs` `load/2`.

## Side Effects
- None. Pure type and conversion definitions; no I/O.

## Verification
- Run: `mise run lint` (cargo fmt check, cargo check, clippy) and `mise run test` (ExUnit against ScyllaDB via Testcontainers; requires Docker).
